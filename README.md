# DSN Mart Sales Prediction --- Standalone 1067.13140 Pipeline

## Overview

This project contains a standalone reconstruction of the DSN Mart sales
prediction pipeline associated with the historical **1067.13140
leaderboard RMSE**.

The task is to predict `total_sales` for a product at a specific DSN
Mart store using product, price, visibility, store, and location
attributes.

The notebook trains all required models from the raw competition data
and does **not** depend on previously generated prediction CSVs or
serialized models.

## Required Files

Place these files in the same directory:

-   `train.csv`
-   `test.csv`
-   `sample_submission.csv`
-   `DSN_Mart_1067_13140_Standalone.ipynb`

The notebook does not require old prediction CSVs, cached OOF
predictions, `.pkl`, or `.joblib` files.

## Dataset

The dataset includes `id`, `product_code`, `product_weight_kg`,
`fat_content`, `shelf_visibility`, `product_category`, `product_price`,
`store_code`, `store_age_years`, `store_size`, `store_location_tier`,
`store_format`, and the training target `total_sales`.

## Final Approach

The recovered final prediction recipe is:

``` text
Final Prediction =
    0.50 × Audited GBR
  + 0.25 × StoreCategoryLinear (minimum 30 observations)
  + 0.25 × ShrunkStoreCategory (alpha = 100)
```

### 1. Data Cleaning

The notebook standardizes categorical values, handles missing product
weights, normalizes fat-content labels, and creates deterministic
product/store interaction identifiers.

### 2. Audited Gradient Boosting Regressor

The main model uses target-free deterministic features. No
target-encoded feature is supplied to this GBR.

``` python
GradientBoostingRegressor(
    n_estimators=600,
    learning_rate=0.025,
    max_depth=2,
    min_samples_leaf=10,
    min_samples_split=12,
    loss="squared_error",
    subsample=1.0,
    random_state=2026
)
```

### 3. Store-Price Linear Model

The store-price model uses standardized price
`(product_price - 140) / 60`, store one-hot indicators, store × price
interactions, and ordinary `LinearRegression`.

It provides the fallback prediction for the store-category components.

### 4. StoreCategoryLinear

A local linear relationship between standardized product price and
`total_sales` is fitted for each `(store_code, product_category)` group.

The local regression requires at least 5 observations and 3 unique
prices. In the final hard-threshold component, it is used only when the
group has at least **30 observations**; otherwise the Store-Price Linear
prediction is retained.

### 5. ShrunkStoreCategory

The local store-category prediction is shrunk toward the Store-Price
Linear baseline using:

``` text
weight = n / (n + 100)
```

Groups with fewer than 5 observations receive zero local weight.

### 6. Final Ensemble

``` python
final_prediction = (
    0.50 * audited_gbr
    + 0.25 * store_category_hard30
    + 0.25 * store_category_shrink100
)
```

Predictions are clipped to remain non-negative.

## How to Run

1.  Install Python 3.
2.  Install the required packages:

``` bash
pip install pandas numpy scikit-learn
```

3.  Put `train.csv`, `test.csv`, `sample_submission.csv`, and the
    notebook in the same folder.
4.  Open `DSN_Mart_1067_13140_Standalone.ipynb` in VS Code, Jupyter
    Notebook, or JupyterLab.
5.  Restart the kernel and run all cells from top to bottom.
6.  Submit the generated `submission_beat1068_robust.csv`.

## Output

The notebook generates:

``` text
submission_beat1068_robust.csv
```

with the required schema:

``` text
id,total_sales
```

The notebook checks ID ordering and uniqueness, complete test coverage,
finite predictions, and non-negative predictions.

## Reproducibility and Leakage Controls

The Audited GBR uses predictor-only feature engineering and does not use
`total_sales` to construct its features.

Store-category models use training targets only to fit their local
regressions. Test targets are never accessed.

The Audited GBR uses `random_state=2026`.

Historical prediction CSVs are not required.

## Historical Score

The **1067.13140 RMSE** is the historical competition leaderboard result
associated with the recovered pipeline.

This is not a locally calculated validation score. Since leaderboard
target values are unavailable to the notebook, rerunning the notebook
cannot independently calculate or guarantee that leaderboard value. Its
purpose is to reproduce the recovered training and inference recipe.

## Evaluation Metric

The competition uses **Root Mean Squared Error (RMSE)**:

``` text
RMSE = sqrt(mean((actual_sales - predicted_sales)^2))
```

Lower RMSE is better.
